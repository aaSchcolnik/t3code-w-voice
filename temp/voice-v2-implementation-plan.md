# On-Device Voice Transcription — Final Implementation Plan (v2)

**Repo:** t3code monorepo (`/Users/aaschcolnik/.t3/worktrees/t3code/t3code-74f10f0d`)
**Engine:** [transcribe.cpp](https://github.com/handy-computer/transcribe.cpp) (MIT, GGUF/ggml, Metal/Vulkan/CUDA/CPU)
**Default model:** `parakeet-tdt-0.6b-v3` (multilingual, 25 langs) — Q8_0 (740 MB) desktop/server, Q4_K_M (~500 MB) mobile default.

This is the finalized plan after an adversarial audit (feasibility, codebase-fit, UX/scope passes). Every blocker-class finding is resolved below; several change the architecture materially versus the draft (utility-process hosting, real packaging pipeline, `voice.enabled` gating semantics, commit-time alias re-pass, promoted server backend). Rejected findings are called out explicitly with rationale.

### Findings rejected (with rationale)

- **"Move scheduling to JS driven by lightweight native RMS events, PCM stays native"** (alternative fix offered for #10, minor, RN engine duplication) — **Rejected as the primary fix.** Shipping PCM off the RN JS bridge for the local path is a deliberate performance/battery decision (avoiding bridge serialization of 16kHz audio); moving VAD scheduling to JS would still require getting frame-level RMS across the bridge at ~50-100Hz, which is worse than the audio itself. We keep native VAD+chunking in Swift and de-risk drift with a shared golden-vector conformance suite instead (accepted half of the finding).
- **Promoting Android RN support into the committed roadmap** — not raised as a blocker by any audit; explicitly deferred to M4 per the draft. No transcribe.cpp Android prebuilts exist today (an NDK/CMake build would be new infra work with no precedent in this repo). Kept as backlog.
- **Full TypeWhisper-style auto-learning (AX edit-diff, guided training)** — all three audits treat this as correctly deferred; it is a large standalone feature. Kept as backlog (§4.6), schema left extensible (`source: "autoLearned"`).
- **Streaming-model support (`streamEngine.ts`) as a committed milestone** — no audit flagged this as urgent; the chunked loop is proven (matches the existing sidecar's real-world behavior) and is model-agnostic. Kept as M4 backlog item, unblocked by the shared `chunkedEngine`/`Recognizer` seam so it costs nothing today.
- **"Universal/fat build must bundle both arch packages with runtime selection"** (part of the packaging finding) — investigated in §1.4: the repo's desktop artifact pipeline builds **per-arch, not universal**, so this sub-case doesn't apply today. Documented as a constraint (no universal macOS build) rather than solved, since building one isn't otherwise in scope.

## 1. Architecture

### 1.1 Per-platform inference hosts

```
                         packages/voice-core (pure TS)
                         DictationTranscriber iface · ChunkedTranscriptionEngine · energy VAD · alias engine
                         model catalog (sha256/bytes/WER) · downloader core
                                              |
        -----------------------------------------------------------------------------------------
        |                          |                                    |                        |
Electron renderer           Plain browser                          RN iOS                    apps/server (M2)
DictationTranscriber   DictationTranscriber                    same event union         TranscribeCppEngine
   |                          |                                     |                     (new, alongside
   v                          v                                     v                      the FluidAudio
desktopTransport(IPC)   remoteTransport (RPC)             t3-transcribe Expo module        sidecar engine)
   |                          |                            (native capture+inference,       selectable via
   v                          v                             or capture-only + RPC           VoiceSettings.engine
utilityProcess:          apps/server                         fallback when no model
DesktopTranscriptionService TranscriptionService              downloaded)
(transcribe-cpp npm,     -> asr-sidecar (FluidAudio,
 koffi, Metal)              unchanged) OR
                            -> TranscribeCppEngine (M2, new)
```

- **Electron**: renderer keeps the existing worklet capture (`/voice/t3MicCapture.worklet.js`) and downsampling. Audio crosses the preload bridge as bytes (`Schema.Uint8Array` over the Float32 buffer — see §2, correcting the draft's incorrect "transferable" claim: `contextBridge`/`ipcRenderer.invoke` structured-clones, it does not transfer). Inference runs in a dedicated **Electron `utilityProcess`** (not main — see §1.2), communicating with main over a `MessageChannel`/`MessagePort`, with main relaying renderer IPC to/from the utility process using the existing `DesktopIpc.makeIpcMethod` + `webContents.send` subscription pattern (`preview.ts` precedent) for the renderer-facing half.
- **Plain browser**: after M2, browser clients get a **real model picker** talking to the server's new `TranscribeCppEngine` (in addition to the existing FluidAudio sidecar engine) — this directly answers the "any device, any model" half of the problem statement that M1-only would have left unserved. Before M2 ships, the panel shows "on-device unavailable in browser; inference runs on the server (fixed model)" exactly as drafted.
- **RN iOS**: mic capture (AVAudioEngine tap, 16 kHz mono Float32) and inference both live in the native module — PCM never crosses the JS bridge for the local path. The module runs the same chunked-VAD loop in Swift and emits `partial`/`final` events shaped exactly like `TranscriptionUpdate`, **plus** a separate `audioLevel` event (RMS, 0-1, ~10Hz) consumed only for the waveform UI — kept outside the `TranscriptionUpdate` union so the cross-platform contract stays byte-identical. The module also supports a **capture-only mode** (mic tap + level events, no local inference) so the RPC/remote fallback path has audio when no model is downloaded — this was missing from the draft's M3 file table and is now explicit (§5 M3).
- **Server**: unchanged (FluidAudio sidecar) through M1; M2 adds a selectable `transcribe-cpp` engine reusing `voice-core`'s `chunkedEngine`, making server inference portable to Linux/Windows and giving browser users a model choice.

Shared RPC-atom code: mobile does **not** clone `apps/web/src/state/transcription.ts`. The three transcription atoms move into `packages/client-runtime/src/state/transcription.ts` as `createTranscriptionAtoms(runtime)`, following the existing `terminal.ts`/`vcs.ts`/`server.ts` factory pattern, and both `apps/web` and `apps/mobile` consume the factory. This is a small refactor of an already fork-owned file, done in M0/M1, not a new clone in M3.

### 1.2 Engine session semantics (all local engines)

- One session at a time per device. transcribe.cpp allows one compute in flight per model — the chunked loop coalesces: a partial tick that fires while a run is in flight is skipped, rerun on the next tick with the fuller buffer.
- VAD constants ported from the sidecar: `SILENCE_RMS=0.012`, `PARTIAL_INTERVAL=1.2s`, `SILENCE_TO_FINALIZE=0.9s`, `MAX_SEGMENT_SECONDS=60`.
- **Adaptive cadence (new, resolves the O(n) finding):** the engine measures wall-clock RTF of each re-transcription tick. If a model's realtime factor on the current tick drops below ~5x, the engine (a) stretches `PARTIAL_INTERVAL` (fewer, larger re-runs instead of constant restarting), and (b) shortens the effective `MAX_SEGMENT_SECONDS` cap so a slow CPU-only host (e.g., an Electron user who picked `whisper-large-v3-turbo` on a non-Metal machine) never accumulates a segment whose finalize takes tens of seconds. The model picker surfaces a coarse "expected speed on this device" indicator (fast/normal/slow), computed from a one-time ~2s calibration transcription run after first download, so users on weak hardware self-select smaller models.
- Abort: `stopAndCommit` triggers `finalize` (one last full-segment run) → `final` → `ended`; `cancel` uses the abort callback and discards.
- **Electron process placement (changed from draft):** `DesktopTranscriptionService` runs inside an Electron `utilityProcess` (`utilityProcess.fork`), not the main process. Rationale: hosting a 0.6-0.9GB resident model plus pre-1.0, ABI-unstable native code (koffi + ggml/Metal) in main means a native crash takes the whole app down, and repeated load/unload cycles fragment main's heap for the app's lifetime. In a utility process: a crash is isolated and observable (`utilityProcess.on("exit")` → surface a transcription error, offer restart), and the idle-reaper becomes "kill the utility process" for full memory reclaim instead of hoping the native lib frees cleanly. IPC shape to the renderer is unchanged; main is a thin relay.
- **Conformance suite (resolves TS/Swift duplication):** a checked-in set of golden fixtures — synthetic PCM sequences (WAV or raw Float32) with expected `TranscriptionUpdate` sequences (segmentId monotonicity, partial-replace timing, finalize triggers) — runs against both `chunkedEngine.ts` (vitest, fake `Recognizer`) and the Swift port (XCTest, fake recognizer protocol). CI fails if either diverges from the fixture-defined expected sequence. This doesn't eliminate the duplication but bounds behavioral drift, which is the actual risk.
- Model load is lazy + reaped, matching `TranscriptionService.ts`'s idle-reaper pattern, adapted to "idle timeout → terminate utility process."

### 1.3 Language handling (resolved, not left as an open question)

- transcribe.cpp's TS binding exposes `capabilities.languages` / `supports_language_detect` per model (backed by `src/arch/parakeet/capabilities.cpp` GGUF KV data) — the plan **no longer proposes empirical testing** as a gating step; the app reads this field at model-load time.
- `parakeet-tdt-0.6b-v3`: `supports_language_detect === false` per `docs/models/parakeet.md` ("no auto-detect — language hint required"), and its `languages` list is the ~25-language European set. Whisper models report `supports_language_detect === true`.
- Resolution rule: at session start, if `capabilities.supports_language_detect`, pass no hint (auto). Otherwise pass `settings.voice.language` if explicitly set by the user; else derive from device locale **only if the derived language is in `capabilities.languages`**. If the locale-derived language is unsupported by the selected model (e.g., `ja`/`zh`/`ko`/`ar` against Parakeet v3's European-only set), do **not** silently pass a wrong hint — show a one-time inline warning ("Your language may not be supported by <model>; consider a Whisper model or switch to server mode") and fall back to `voiceInferenceMode` resolving to `server` for that session if a working sidecar exists, else proceed with the closest hint and a visible low-confidence badge.
- Voice settings gets an explicit language row regardless (matches draft), now sourced from `capabilities.languages` for validation instead of being freeform.

### 1.4 Electron packaging (rewritten — draft targeted a nonexistent file)

The draft's M1 table listed "electron-builder config | modified" — **there is no electron-builder config in this repo.** Desktop packaging is the custom pipeline in `scripts/build-desktop-artifact.ts` (repo root, not under `apps/desktop/`), which already stages an explicit `node_modules` tree, defines `DESKTOP_ASAR_UNPACK`, and special-cases native deps (the `node-pty` symlink-surgery precedent). This plan's M1 packaging work is:

1. **Extend `DESKTOP_ASAR_UNPACK`** in `scripts/build-desktop-artifact.ts` to include `transcribe-cpp/**` and `koffi/**` (koffi's `.node` addon must load from disk, same as any native module already staged there) — explicitly, not relying on any electron-builder `smartUnpack` auto-detection (which doesn't apply here since there's no electron-builder config to begin with).
2. **pnpm-aware staging:** `node_modules/transcribe-cpp` and its platform optionalDependency (`@transcribe-cpp/darwin-arm64-metal` etc.) are symlinks into `node_modules/.pnpm/...` in this workspace. The staging step must resolve symlinks to real files when copying into the packaged app (following whatever the script already does for `node-pty`, which has the same symlink shape) — verified as real work, not a one-line glob.
3. **Per-arch package resolution:** the artifact pipeline builds **per target arch** (confirmed: no universal/fat macOS build exists in this repo's pipeline), so pnpm's `os`/`cpu` field filtering naturally installs only the host-matching `@transcribe-cpp/*` package when each arch's build runs on matching CI hardware. The plan adds an explicit assertion in the build script: fail the build if the expected `@transcribe-cpp/<platform-arch>` package is absent from the staged tree for the target arch, rather than silently shipping an app that crashes on first `transcribe()` call.
4. **Codesigning/notarization:** every unpacked dylib (`libtranscribe.dylib`, ggml backend dylibs, `koffi.node`) must be re-signed with the team identity under hardened runtime for the app to notarize. This plan adds a `codesign --verify --deep` + `spctl -a` check for the unpacked native tree to the same post-build verification step the pipeline already runs (wherever it currently verifies `node-pty`'s native binary — same location).
5. **Version lockstep:** one upstream `transcribe.cpp` release tag governs, per milestone: the `transcribe-cpp` npm version (pin exact — `0.1.3` is latest at plan time; **do not** float to `latest`), the vendored `TranscribeCpp.xcframework` release asset (M3), and the vendored Swift wrapper source (`bindings/swift`, no published SwiftPM mirror, must be copied — M3). Recorded in a single `VERSION` file per the `apps/mobile/modules/t3-terminal/Vendor/libghostty/VERSION` precedent. Mixing tags (e.g., v0.1.3 xcframework + wrapper source from `main`) is an ABI mismatch the binding's abihash check would only catch at runtime — this rule prevents that class of bug outright.
6. **Packaged smoke test** (M1 exit criterion, revised): run `scripts/build-desktop-artifact.ts` for the target arch, then assert (a) the packaged app's `artifactDir()`-equivalent resolves to a real unpacked directory containing `koffi`'s `.node` and the correct platform package, (b) `codesign --verify --deep` and `spctl -a` pass on the unpacked native tree, (c) a scripted launch transcribes a checked-in WAV via whisper-tiny (46MB, fast to fetch) end-to-end.

### 1.5 Mobile device floor (resolved — draft's benchmark gate didn't match the actual device floor)

- iOS 16 (the xcframework's floor, matching `t3-terminal`'s existing 16.1 precedent) includes iPhone 8/X-class devices: A11, 2-3GB RAM, jetsam ceiling ~1.1-1.4GB. Q4_K_M Parakeet v3 (~500MB resident) plus RN app baseline is tight-to-over-budget on those devices, and ggml-Metal's simdgroup-matmul kernels need Apple GPU family 7+ (A14+) — pre-A14 devices fall back to CPU, where a 0.6B model may not hit realtime and will run hot.
- **Runtime capability gate (new):** before any local model load, `t3-transcribe` checks (a) `os_proc_available_memory()` (or the RN-exposed equivalent) against a per-model `minRamMb` from the catalog, and (b) GPU family via `MTLDevice.supportsFamily(.apple7)`. Below floor, local inference is refused outright (not just discouraged) and the session transparently resolves to the RPC remote-fallback path with a one-time explanatory toast — this is a hard gate, not a UI hint, closing the finding that catalog `minRamMb` existed with no enforcement.
- Floors, concretely: Parakeet v3 (any quant) and any model >600MB requires Apple7+ GPU (A14+) and ≥4GB device RAM; `parakeet-tdt_ctc-110m` and `whisper-tiny`/`whisper-base` are allowed down to A12/3GB (CPU fallback acceptable at that size).
- **Benchmark gate widened:** M3's device-benchmark task (RTF, peak RSS, thermals — no published iPhone numbers exist for this model) now runs on both an A15-class device (for the "recommended" tier) **and** an A12/A13-class device (to validate the floor gate itself correctly refuses/degrades rather than just assuming). Mobile ships local as opt-in until this task's results are in; the benchmark gates whether local becomes the mobile _default_ vs. staying an explicit opt-in with server as default.

### 1.6 Reconciling `voiceInferenceMode=local` with server-shared `voice.enabled` (new — was entirely unaddressed in the draft)

Verified against the real code: `ChatComposer.tsx` gates the mic button and voice keybinding entirely on `settings.voice.enabled` (per-environment, server-shared, default `false`) — confirmed at `ChatComposer.tsx:1708,1722,2587,2918`. The draft's "zero new lines in `ChatComposer.tsx`" claim is **retracted**; this is a real gap: an Electron user with a fully-downloaded local model, in a thread against a remote environment whose server admin never turned voice on, would see no mic button at all, even though their inference never touches that server.

**Gating rule (new):** the mic is shown when `environment.settings.voice.enabled === true` **OR** (`localCapability.present === true` AND the per-device `voiceInferenceMode !== "server"`). `localCapability.present` means: running in Electron (or RN) with a downloaded model and (on mobile) passing the §1.5 runtime gate. This is computed by a small new hook, `useVoiceAvailability(environmentId)`, consumed at the two `ChatComposer.tsx` call sites instead of the raw `settings.voice.enabled` boolean — a genuinely small (~15-20 line) diff to a shared file, tracked explicitly in the fork-sync table (§5 M1), not glossed over.

Clarifications this rule forces:

- The new `VoiceSettingsPanel`'s "enable" toggle continues to write `ServerSettingsPatch.voice.enabled` for the **currently active environment's** server only (unchanged semantics — it does not retroactively affect other environments' mic visibility; it just becomes one of two ways the mic can show).
- `transcriberFactory`'s `auto` resolution (§1.8) is the thing that actually decides local vs. server _once the mic is shown_; `useVoiceAvailability` only decides _whether to show the mic at all_.
- This is added to the M1 exit criteria explicitly (§5).

### 1.7 Why the server transcribe.cpp engine is promoted to committed M2 (not backlog)

The problem statement's primary framing is "run inference on the local device where the user actually is (web/Electron **and** React Native)," but plain-browser use against a remote server — explicitly called out in the problem statement as a target scenario — gets zero benefit from M1/M3 alone: no model picker (hidden in-browser), and the sidecar is hardcoded FluidAudio Parakeet with no choice. Leaving this to an "optional M4" backlog item means the plan doesn't actually satisfy requirement #2 ("a model picker... download/select any model") for a whole class of users the problem statement names directly. The engine itself reuses `voice-core`'s `chunkedEngine`/`Recognizer` seam (same ~250 loc estimate as the draft's M4.1), so promoting it doesn't expand scope much — it resequences work that was going to happen anyway. It's now **M2**, run in parallel with the alias milestone since they touch disjoint files.

### 1.8 `auto` mode resolution (changed — draft's rule silently regressed existing users)

Draft's open question #3 proposed "local wins whenever a model is downloaded" for `auto` mode. Rejected as the default because it silently trades a working setup (FluidAudio's real language auto-detect, ANE power efficiency) for a materially different one (locale-derived hint only, Metal power draw) the moment a user downloads _any_ model for _any_ reason, with no visible signal that behavior changed underneath them.

**Revised rule:** `auto` resolves to **`server`** by default for any environment where the server-side sidecar is reachable and `voice.enabled`, _unless_ the user has explicitly visited the voice settings panel and either (a) explicitly set `voiceInferenceMode = "local"`, or (b) gone through the first-run local-model consent flow (§3.4), which itself sets the per-device mode explicitly rather than leaving it on `auto`. In other words, **`auto` no longer silently prefers local** — it prefers whatever a user hasn't actively chosen to change, and any switch to local is a deliberate, visible action (the consent dialog), not an emergent side effect of downloading a model for testing. For environments with no reachable server sidecar (or `voice.enabled=false`) and a downloaded local model, `auto` does resolve to local — there's no regression to protect since server was never viable there.

## 3. Model manager

### 3.1 Catalog (generated at build time, not hand-typed)

A build-time script (`packages/voice-core/scripts/generate-catalog.ts`, run in CI and checked into `catalog.json`) reads transcribe.cpp's `docs/models/*.md` cards (63+ models, each already carrying size/WER/language metadata) and the HF tree API (`lfs.oid` for sha256, `size` for bytes) to produce entries — this replaces the draft's hand-typed table (which had verified errors: `whisper-large-v3-turbo` 886MB vs. research's 845MB; Parakeet v3 Q4_K_M 485 vs. 502MB disagreement in sources). ### 3.2 Download mechanics

- URL: `https://huggingface.co/handy-computer/<model>-gguf/resolve/main/<model>-<QUANT>.gguf`, Range-resumable.
- Write to `<file>.part`, hash incrementally while streaming, verify against pinned sha256, atomic rename.
- **Free-space preflight (new):** before enqueueing, check available space (Electron: `statfs` on the `userData` volume; iOS: native module, since neither `expo-file-system` API surface reliably exposes this — see §3.3) against the model's byte size + 10% margin; refuse with a clear error if insufficient, before any bytes are written.
- **Disk-full mid-download (new):** ENOSPC during streaming moves the entry to an explicit `error: "disk_full"` state, deletes the `.part` file, and surfaces a retry-after-freeing-space action.
- **Delete-selected-model semantics (resolved):** deleting the currently-selected model is allowed but requires confirmation and immediately flips the per-device `voiceInferenceMode` resolution to `server` for that session (not silently blocked, not silently switched without telling the user).
- **Quant-mismatch semantics (resolved):** `voiceModelQuant` is validated against what's actually on disk at session start; if the setting references a quant that isn't downloaded, the picker's "select" action becomes the source of truth (selecting always implies "ensure this exact quant is downloaded"), and stale settings values are corrected on read rather than causing a runtime error.
- Storage roots: Electron `app.getPath("userData")/voice-models/` (via `DesktopEnvironment`); server (M2) `stateDir/voice-models/`; RN via the native module (§3.3).
- Sideload: unknown `.gguf` files in the models dir surface as "Custom" catalog entries (Handy pattern).

### 3.3 Mobile download & storage (corrected API usage)

The draft mixed `expo-file-system`'s new `Paths.document` API (no pause/resume, no backup-exclusion hook) with the legacy `createDownloadResumable` (which needs `expo-file-system/legacy` in the pinned ~56 version) and assumed a nonexistent `NSURLIsExcludedFromBackupKey` setter. Resolved: **downloading and backup-exclusion both move into the `t3-transcribe` native module**, which is being written anyway (§5 M3) and has natural access to `URLSession` background downloads (pause/resume/resume-after-kill) and `[NSURL setResourceValue:forKey:NSURLIsExcludedFromBackupKey:]`. JS only drives start/pause/cancel/progress-subscribe through the module's event surface; no `expo-file-system` API is used for model files (it may still be used elsewhere in the app unrelated to voice).

### 3.4 First-run download UX (new — was an unresolved open question sitting on M1's critical path)

Specified explicitly, pulled into M1 scope:

1. First mic press with `voiceInferenceMode` unresolved and no model downloaded (Electron only — this flow doesn't apply to browser or to RN's opt-in-gated local mode) shows a **one-time consent dialog**: model name, size (740MB default), estimated download time at typical broadband, and a note that inference will run on-device afterward. One tap to proceed.
2. On confirm: the session **starts immediately over the existing server RPC path** (if a sidecar is reachable) while the model downloads in the background; the composer shows a subtle inline download-progress affordance (not a modal) alongside normal dictation. Once the download completes and verifies, subsequent sessions use local automatically (per §1.8's rule — this counts as the explicit user action that sets `voiceInferenceMode`).
3. If no sidecar is reachable (no server configured) and the user declines to wait: dictation is unavailable with a clear message, not a silent no-op.
4. Download failure mid-flow (network error, hash mismatch, disk full): toast + the panel's model row shows the specific error state from §3.2; the in-progress dictation session (if any) is unaffected since it was running server-side during the download.
5. Offline on first use with no server configured: the consent dialog is not shown (nothing to download); mic press shows "voice dictation needs either a network connection to download a model, or a configured server."

This flow is now explicitly part of the M1 exit criteria (§5), closing the gap where the draft's exit criterion ("dictates locally with Parakeet v3") depended on an unspecified UX.

## 4. Aliases (dictionary)

### 4.1 Data model — new field on `ServerSettings.voice`, in the repo's verified Effect v4 style (`settings.ts:398-459`)

```ts
export const VoiceDictionaryEntry = Schema.Struct({
  id: Schema.String,
  type: Schema.Literals(["term", "alias"]),
  originals: Schema.Array(Schema.String),
  replacement: Schema.optionalKey(Schema.String),
  caseSensitive: Schema.Boolean.pipe(Schema.withDecodingDefault(Effect.succeed(false))),
  fuzzy: Schema.Boolean.pipe(Schema.withDecodingDefault(Effect.succeed(false))),
  enabled: Schema.Boolean.pipe(Schema.withDecodingDefault(Effect.succeed(true))),
});
export type VoiceDictionaryEntry = typeof VoiceDictionaryEntry.Type;

// VoiceSettings (settings.ts:398) gains:
dictionary: Schema.Array(VoiceDictionaryEntry).pipe(Schema.withDecodingDefault(Effect.succeed([]))),
engine: Schema.Literals(["sidecar", "transcribecpp"]).pipe(Schema.withDecodingDefault(Effect.succeed("sidecar"))),
```

`ServerSettingsPatch.voice` (`settings.ts:582`, currently `Schema.optionalKey(...)`) additionally gets `dictionary: Schema.optionalKey(Schema.Array(VoiceDictionaryEntry))` and `engine: Schema.optionalKey(...)` in the same block.

**Version-skew handling (new):** an older server that hasn't picked up the new patch fields will, per the repo's existing patch-decode behavior (verified: unknown/extra patch keys are stripped by the schema decoder rather than rejecting the whole write — confirmed against `ServerSettingsPatch`'s structural decode), silently drop `dictionary`/`engine` writes rather than failing the entire settings save. The Dictionary UI detects this (patch echoed back from the server doesn't reflect the write) and shows a "this server doesn't support dictionaries yet — update it" read-only notice instead of silently discarding user edits with no signal.

### 4.2 Matching engine (`packages/voice-core/src/aliases/`)

- **Exact tier (always on):** entries expanded per variant, sorted longest-first; case-insensitive unless `caseSensitive`; Unicode word boundaries via lookaround `(?<![\p{L}\p{N}])…(?![\p{L}\p{N}])/u` on platforms that support it; plain substring match for CJK/Thai/no-space-script variants.
  - **Capitalization fix (new, resolves the "gonna → going to" sentence-start bug):** when the replacement text is entirely lowercase, transfer the matched text's first-letter capitalization onto the replacement (so a sentence-initial match capitalizes correctly). Mixed-case replacements (e.g., `ComplyCube`) are inserted verbatim regardless of position — this preserves brand casing while fixing generic lowercase replacements. Golden tests cover both cases explicitly (§6).
  - **Hermes compatibility (new):** M0 adds a one-line runtime probe (`try { new RegExp("(?<=x)y", "u") } catch { ... }`) run in the RN (Hermes) test target, not just Node/vitest, since Hermes's lookbehind/Unicode-property-escape support has historically lagged V8/JSC and a silent construction failure would make the fail-open wrapper (below) mask aliases no-op-ing on all of mobile with nothing catching it. If unsupported, the engine falls back to `boundary.ts`, a hand-rolled scanner (VoiceInk's approach: code-point classification instead of regex lookaround) used uniformly instead of the regex path when the probe fails, keeping behavior identical across engines rather than degrading silently on one platform.
- **Fuzzy tier (opt-in per entry):** 1-3 word n-gram scan; token normalization (strip non-alphanumerics, lowercase); length prefilter; score = normalized Levenshtein ×0.3 when phonetic codes match (Soundex/double-metaphone); accept < 0.18; case-pattern + surrounding-punctuation preservation from matched text (unchanged from draft — already correct here).
- **Fail-open:** the whole post-pass is wrapped so any throw returns the raw text untouched — a matcher bug must never eat a transcript.
- **Applied to finals only** at the per-segment level (unchanged principle) — **plus** a second pass at commit time (§4.3, new).

### 4.3 Application points (revised — closes the stop-drain and cross-segment gaps)

Verified against `useVoiceDictationSession.ts`: `finalizeCapture` (lines 90-109) computes `committedTranscript = renderTranscriptBuffer(segmentsRef.current)` and calls `onCommitRef.current(committedTranscript)`. Two real gaps existed in the draft's "apply on each `final` update" design:

1. The 800ms `STOP_FINALIZATION_DELAY_MS` path (`requestStop`, line 111 onward) can call `finalizeCapture(capture, { commit: true })` while a segment has only ever received `partial` updates (no `final` arrived in time) — that segment's raw, unprocessed text would be committed.
2. Segments are joined with `renderTranscriptBuffer` before commit; a brand phrase split across a segment boundary (e.g., "Comply" finalized in segment N, "Cube" starting segment N+1) can never match a multi-word alias applied only per-segment.

**Fix:** the alias engine additionally runs once more over the fully joined `committedTranscript` string inside `finalizeCapture`, immediately before `onCommitRef.current(committedTranscript)` is called (line 106-108). The exact tier is idempotent (matching already-correct text doesn't re-match), so double-application (once per-segment for live display polish, once at commit for correctness) is safe. This is the only change proposed inside `finalizeCapture`; the rest of the stop/commit control flow is untouched.

- RN: identical two-pass application inside the mobile hook's equivalent commit path.
- Server-side application remains deliberately avoided (one implementation, one behavior, per the draft's original reasoning — unchanged).

### 4.4 Model biasing (M2, unchanged in mechanism, fixed data-flow)

Probe `capabilities.supportsInitialPrompt` (Whisper only today; Parakeet has no biasing mechanism — verified against `src/arch/parakeet/` having no hotword/prompt path). When supported, join enabled `term` originals + alias replacements into an `initial_prompt`, clipped to ~600 chars (224-token limit).

**Data-flow fix (new, resolves the draft's gap):** `DesktopTranscriptionService` runs in a utility process with no subscription to any environment's server settings (it's intentionally settings-stateless — §1.2). The renderer, which _does_ observe `ServerSettings.voice.dictionary` via existing settings atoms, assembles the enabled-terms prompt string and passes it as part of the `startSession` IPC payload (`voice-local.ts` schema gains a `promptHint?: string` field on the session-start input). Main/utility-process code never queries settings directly.

Still runs the exact tier deterministically afterward; skips the fuzzy tier for prompted words (avoids double-correction).

### 4.5 UI

"Dictionary" section inside the new Voice settings panel: table (spoken variants, replacement, fuzzy toggle, enabled toggle, delete), inline add row, edit sheet, following `ProviderModelsSection.tsx`/`KeybindingsSettings.tsx` editable-list patterns. JSON import/export. Writes go through `useUpdatePrimarySettings()` → `ServerSettingsPatch.voice.dictionary`, with the version-skew degraded state from §4.1 wired in.

### 4.6 Deferred

TypeWhisper-style auto-learning (guided training / AX edit-diff correction capture) — explicitly out of scope for this plan; the schema's `id`/`type` fields leave room for a `source: "autoLearned"` extension later (unchanged from draft; no audit disputed this deferral).

## 6. Testing strategy

**M0:** VAD against synthetic PCM (silence/speech/hangover edges); `chunkedEngine` with a fake `Recognizer` — segmentId monotonicity, partial-replacement semantics, tick coalescing under a slow recognizer, adaptive-cadence behavior under a simulated low-RTF recognizer, finalize on silence/stop/60s cap; downloader against a mock HTTP server — resume after kill, sha mismatch → reject + `.part` cleanup, pause/cancel, ENOSPC simulation; alias engine golden-case suite including the Hermes-probe test (run in the RN/Hermes test target, not just vitest) and the boundary-scanner fallback path; the golden-vector fixture set that M3 will replay against XCTest is authored and validated against the TS engine here first.

**M1:** unit tests for both transports (fake bridge / fake atoms) proving identical `TranscriptionUpdate` streams; existing `MicButton.browser.tsx`/`VoiceRecordingOverlay.browser.tsx` pass unchanged (proof the seam is clean); `useVoiceAvailability` unit tests covering all four combinations of (`voice.enabled` × local-capability-present) from §1.6; a gated manual/nightly Electron integration test loading whisper-tiny and transcribing a checked-in WAV via the utility process (including a forced-crash test: kill the utility process mid-session, assert the renderer surfaces a clean error and can restart); packaged-build smoke test per §1.4 item 6 (unpack + codesign/notarize + scripted transcribe); manual `test-t3-app` pass for browser fallback, mode switching, and the first-run consent-dialog flow (§3.4) end to end including the background-download-while-dictating-remotely path; latency measurement (cold/warm) on M-series and an x64 CPU-only machine, including the adaptive-cadence behavior with `whisper-large-v3-turbo` on the slow machine.

**M2:** alias golden-case suite — the ComplyQ/"Comply Q"/"comply cube" family via one fuzzy term entry; boundary vs. punctuation; CJK substring path; case-pattern preservation (both the fuzzy-tier and the new exact-tier sentence-start capitalization fix); longest-first overlap; fail-open (throwing matcher returns raw text); prompt clipping at 600 chars; **the commit-time double-pass** — a test that forces a segment to only ever emit `partial` (never `final`) before the 800ms stop-drain fires, asserting the committed text is still alias-corrected, plus a cross-segment-phrase-split test ("Comply"/"Cube" in adjacent segments) verifying the commit-time pass catches what the per-segment pass structurally cannot. Server: `TranscribeCppEngine` against the same conformance fixtures as the Electron path. Version-skew test: an old-shaped `ServerSettingsPatch` response (missing `dictionary`) drives the panel into its degraded read-only state, not a crash.

**M3:** simulator runs via `test-t3-mobile`/`ios-debugger-agent` (CPU-only slice, so sim tests use whisper-tiny/110m); the golden-vector conformance suite runs in XCTest against the Swift engine and must match the TS engine's fixture-defined output exactly (CI gate, not just manual review); a required physical-device benchmark task, now on **both** an A15-class device (recommended tier) and an A12/A13-class device (floor-gate validation, §1.5) — RTF, peak RSS, thermals — gating local-as-default vs. opt-in; jetsam test (backgrounding mid-download and mid-session); download resume over network flap; backup-exclusion verified via an actual iCloud-backup-simulated check (not just "the API was called"); capture-only mode tested as the fallback path when no model is downloaded.
